01

系统总览

上层负责提交与展示；本服务负责调度和校验；Codex 通过模型决定查询步骤，浏览器负责真实访问网站。点击图中任意模块查看职责、输入输出和源码。

逻辑组件与信息流
服务组件Codex / 模型数据 / 校验外部网站证据回流 / 待接入
逻辑图不等同于独立进程；容器边界见第 06 节。
接入层

妙搭服务端代理

从真实登录上下文取得用户身份，添加服务凭证后调用 API。前端只提交提单，不持有模型 Key 或服务 Key。

执行层

一票，一次独立执行

每次尝试创建 Codex 配置、MCP 进程、Chromium 和临时目录。默认全局同时执行 2 票，同航司前缀最多 1 票。

结果层

两层结果，一个来源

首页返回提单号与 ATD / ATA；详情保留空运、公路、拆批、缺失及冲突。证据通过鉴权接口按任务和尝试读取。

接入状态：后端代码、接口协议与妙搭服务端示例已实现。现有妙搭页面尚未切换到此服务；阿里云目标服务器部署尚未完成。图中的外部接入属于既定接入设计。
02

一次查询如何完成

HTTP 提交在任务入库后立即返回。真实网站查询在后台运行，用户关闭或刷新页面不会使队列中的任务消失。

成功路径 · 交互时序图点击步骤，或使用“上一步 / 下一步”阅读处理过程。

时序图是静态流程演示，不会发起真实提单查询；箭头长度不代表耗时。轮询间隔建议 3 秒，由接入端实现。
01 / ACCEPT

格式化与幂等

统一 3+8 格式、去重。同一用户与幂等键重复提交相同列表，复用原批次；不同列表返回 409。

02 / CLAIM

事务领取

SQLite 事务检查全局与航司并发，写入 workerId、attempt 和租约，防止多个 Worker 同时领取一票。

03 / BROWSE

先目录，后官网

先尝试 track-trace。目录失败仍保存访问尝试，再走允许的航司入口；不能把访问失败判作无记录。

04 / VERIFY

校验后返回

模型 JSON 与浏览器证据分别采集。程序检查提单、航段、实际标签、原始时间，再生成首页汇总。

03

任务状态、重试与恢复

批次是多个任务的集合；状态转换发生在单票任务上。一个批次的 finished 仅表示全部任务已结束，不表示全部查询成功。

单票状态机
排队 / 执行有结果终态或受阻
虚线是重试回路。invalid_input 和 succeeded 不支持在原任务上重查。手动重查保留 jobId，attempt 持续增加。

调度与执行预算

约束当前实现
默认并发全局 2；同航司前缀 1；事务内检查
任务租约 / 续约30 秒租约；每 2 秒续约
Worker 活跃心跳每 5 秒；readyz 检查近 30 秒活跃记录
单次查询超时Compose 默认 360 秒；原生未配置时 240 秒
自动重试默认最多执行 2 次；仅可重试异常进入回路
延迟 / 累计上限5 秒 × 当前 attempt；手动重查累计最多 6 次
浏览器 / 输出预算80 次操作计数；stdout + stderr 上限 8,000,000 字节

四种异常如何处理

Worker 崩溃或服务器重启

未完成记录仍在数据库中。下次领取任务时清理过期租约：预算内回到 queued，否则 failed；已取消的任务转 cancelled。可能重复一次只读查询，不承诺 exactly-once。

用户取消，成功结果恰好晚到

取消标记先持久化。运行任务通常在下一次 2 秒心跳中发现取消并终止；写入结果时再次检查，取消优先，不会被晚到成功覆盖。

旧 Worker 恢复后尝试提交

完成写入必须匹配 running 状态、workerId、attempt 和有效租约。旧执行不能覆盖新执行的结果。

验证码尝试未通过 / 登录 / 无有效证据

明确受阻返回 blocked，不无限自动重试，也不向终端用户弹出确认。当前已提供模型看图、图形码填写、局部点选/拖动；受一次性令牌和尝试预算限制，失败保留原因。

succeeded校验后的 complete；首发、末到唯一且全票完成已核实，中间时间可缺失。
partial部分可用、拆批或冲突；可能已有首页 ATD 和 ATA。
not_found对应提单在来源页面有明确无记录文字。
blocked登录、验证码、访问或结果证据不足。
failed / cancelled执行异常且预算用尽，或用户取消。
invalid_input错误号码逐票隔离，不启动 Codex 查询。
04

从网页原文，到可展示时间

模型负责理解与提取；程序负责检查引用与汇总。有效 JSON 只代表格式正确，还需要通过独立的证据链。

双路输入 · 确定性校验证据读取与签名校验由 Runner 完成；结果语义规则在 Worker 中执行。
HMAC 用于核验本次执行的采集包，不是航司签发的数字证明；已发布证据不保留临时签名密钥。

实际时间必须满足的条件

  1. 对应证据来自本次 jobId / attempt，通过采集包签名与正文 SHA-256 校验。
  2. 证据类型为 page，来源不是 track-trace 目录，页面包含当前提单号。
  3. 连续引用 quote 确实存在于页面原文；允许统一空白和字符规范化。
  4. quote 保留实际标签和原始时间；同页上下文可证明提单、航班、机场及批次归属。
  5. 出发标签允许 ATD / DEP / Actual Departure；到达允许 ATA / ARR / Actual Arrival。中文“实际起飞／实际出发”“实际到达／实际抵达”分别映射 ATD / ATA，quote 保留中文原文。
  6. 已标记的时间冲突使相关时间留空，原始冲突值保存在 issues。

首页 ATD / ATA 的汇总规则

情况返回形式
唯一可核实时间kind=value，value 为来源时间字符串
分批、不同时间kind=multiple，value=null，显示多次出发 / 分批到达
来源存在冲突kind=conflict，value=null，详情保留原值
没有有效证据kind=missing，value=null
只有部分记录保留已核实的 value，note 提醒“仅部分记录”
只汇总运单始发 / 最终目的地对应的空运段；公路段在详情中保留。
三个不可替代：navigation_attempt 不能证明实际时间；ETA / STA 不能替代 ATA；交付 DLV 只能辅助判断全程完成，不能替代 ATA。运输时间不推断年份、不转换时区。规则校验仍无法保证模型完全理解复杂表格，也不能发现模型漏报的所有冲突。
05

数据存储与接口边界

数据库保存业务状态；文件系统保存原文与可选截图。查询结果通过 evidenceId 关联来源，通过 attempt 保留各次查询的证据。

持久化实体关系一个 SQLite 文件、五张业务/运行表；证据文件通过逻辑 ID 关联。
batches → jobs、jobs → events 为数据库外键；jobs → 证据目录为逻辑关联。分段、issues、summary 保存在 jobs.result_json。

持久卷 /data

/data/
├── service.sqlite          批次、任务、结果、事件
├── service.sqlite-wal      WAL 日志；备份不能忽略
├── service.sqlite-shm      SQLite 共享内存索引
├── evidence/
│   └── <jobId>/<attempt>/
│       ├── <evidenceId>.json 已验证页面原文与元数据
│       └── <evidenceId>.png  可选截图
└── runs/
    └── <jobId>/<attempt>/
        ├── codex/          任务配置，含临时签名信息
        ├── work/           隔离工作目录
        ├── evidence/       待验签采集包
        ├── schema.json
        └── result.json     模型候选结果

正常结束、超时或可处理异常后，Runner 发布有效证据并清理当前 runs 目录。整机骤停可能留下临时目录；当前未实现自动历史清理。

所有业务接口按 tenant:userId 隔离；证据可用 ?attempt=1 选择历史尝试。

入口只接受提单列表

请求结构为 {mawbs: string | string[]}。额外的 prompt、URL、模型名称、Shell 参数均被拒绝。

身份来自可信服务端

除 healthz 外需 Bearer 服务 Key 和 X-User-Id。提交还需 Idempotency-Key；Key 持有方必须可信，不能向浏览器发放。

就绪不等于查询成功

healthz 只表示 API 存活；readyz 只表示近期 Worker 心跳存在。模型认证与航司连通需要真实 smoke 验收。

06

阿里云部署拓扑

支持单机 Docker Compose 或原生 systemd。下图展示 Docker 拓扑；原生方案直接运行相同的 API 与 Worker 进程，模型推理仍在远端 API 服务。

容器、进程与网络边界下图描述部署设计；不表示服务器已经上线。
浏览器 HTTPS 与公网 IP 代理仅约束 Chromium 的网站出口；模型 API 连接独立使用 CODEX_BASE_URL。Caddy 为可选 https profile。

配置来源与生效方式

配置当前值 / 行为
模型CODEX_MODEL=gpt-6-astra，由 .env / 进程环境传入
推理强度low，当前写死在 runner.ts，尚无环境变量
模型地址CODEX_BASE_URL；自定义 HTTPS Responses 网关或默认 provider
模型凭证仅 Worker 挂载 model_api_key secret
服务凭证仅 API 挂载 service_api_keys secret
修改模型配置更新 .env，再重新创建 Worker 容器；单纯 restart 不加载新环境
修改推理强度当前需改代码、重建镜像并更新 Worker

资源配置与 1GB 服务器

API / Worker 上限512MB / 4GB；这是上限，不是预先占用量。
Worker /dev/shm上限 1GB；按实际使用占用内存。
浏览器内存压力每次执行有独立 Chromium；默认并发 2 会叠加内存峰值。
30GB 磁盘还要容纳操作系统、镜像、构建缓存和证据；当前无自动历史保留策略。
1GB 试运行建议并发设 1、按需配置 Swap、在其他机器构建镜像并实测。此方案尚未在 1GB ECS 验证。
原生部署（不使用 Docker）：HTTPS 反向代理 → systemd API → SQLite ← systemd Worker → Codex / MCP / Chromium。新安装配置默认并发 1，数据位于 /var/lib/codex-flight-service/data，凭证由 systemd 分别注入。进程限制与容器隔离并不等价；1GB 目标机仍需实测。详见 原生部署文档 ↗。本页核心业务图仍对应下方标明的实现基线。
扩容边界：同一 ECS 上可增加 Worker 进程，领取仍受数据库全局限流。跨多台 ECS 时需改造 Store 与队列，并让证据存储可共享；不能直接把 SQLite 放在 OSSFS / NFS 上。当前没有 Redis、PostgreSQL、OSS 或 Kubernetes 组件。
07

边界、验证与源码索引

把“已经实现的控制”“仍需验证的能力”和“未来扩展”分开，避免将架构图理解为部署完成或所有航司均可查询的承诺。

四层控制

接口层：身份与输入

只接受提单号；服务 Key 识别租户，可信 X-User-Id 划分用户；幂等、队列容量与请求速率都由服务校验。越权资源统一返回 404。

执行层：固定能力

每票生成独立 Codex 配置，关闭 Shell、unified exec、插件、Apps、hooks、多 Agent、记忆、内置网页搜索与桌面 Computer Use。仅预授权项目的 10 个 MCP 浏览器工具。

浏览器层：受限网站访问

从 track-trace 开始查询，航司与资源域名无需白名单。仅允许 HTTPS 443 和公网 DNS 解析结果，连接到已检查的 IP。拒绝内网、回环和云元数据地址；重定向与子资源同样检查协议和公网地址。没有任意 JavaScript 执行工具。

证据层：校验与最小暴露

临时 HMAC、正文摘要及 jobId/attempt 防止采集包串用；原文与截图经鉴权返回。日志只提供业务阶段，不公开原始模型推理、凭证或整个网页内容。

明确的能力边界

浏览器工具不是万能自动化

  • 页面内容是不可信资料，不能成为修改系统规则的指令。
  • 验证码自动处理未通过、登录、航司反自动化和页面改版仍可能导致 blocked。
  • 验证码通过现有模型识图；专用工具只接受已发现的验证码字段及图内坐标。短信、邮箱、OTP 和登录验证仍返回受阻。
  • Playwright 默认未启用 Chromium 自身 sandbox；使用独立非 root 容器、只读根文件系统和受限出口降低风险。
  • 证据校验不能替代真实样例回归，复杂表格与冲突遗漏仍需抽查。
