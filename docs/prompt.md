# 查询提示词设计

项目目标：用户提供空运主提单号，服务优先核实首个空运段 ATD、末个空运段 ATA 和全票完成情况，并保留已取得的运输记录及来源证据。缺失、冲突、无记录和查询受阻均如实说明。

运行提示词的唯一来源是 [src/runtime/prompt.ts](../src/runtime/prompt.ts)。所有航司共享同一套规则，仅提单号随任务变化。优先输入完整提单号并点击 Track direct，跟随跳转或新页面完成查询，直达失败或匹配错误时才使用目录。工具参数和操作预算以 MCP 定义与运行配置为准。

## 职责

- 模型：自主查询官网，理解表格、航段和批次，提取原始时间与可复核引用。
- 浏览器：执行受限操作，保存页面原文和截图，返回证据标识。
- 服务：校验证据、处理冲突、计算首末时间汇总并持久化结果。

提示词不重复 JSON Schema，不要求模型生成 Schema 以外的汇总字段，也不包含某张提单的预期答案。成功标准是数据真实、归属明确、信息完整；不能以返回 `complete` 为目标补齐缺失信息。

## 本次 Case 对应的规则

| 页面情况 | 提示词要求 |
| --- | --- |
| 旧入口会话过期，重启跳转到 HTTP | 浏览器将标准 HTTP 链接和重定向升级为 HTTPS；按页面提供的 home/restart 或应用入口恢复会话，再进入公开追踪菜单。Login 标题不等于必须登录，需检查游客查询入口。 |
| 菜单、提交或展开操作超时 | 先读取最新快照，确认菜单或记录是否已经展开，再根据最新引用继续；单次动作超时不等于查询受阻。 |
| 机场代码位于航段标题，实际时间位于下方详情 | 时间 quote 保留连续原文中的实际标签和时间，使用同页上下文核实记录归属，不自行补写机场代码。 |
| 官网使用中文实际时间标签 | 保留中文原文，仅将结构化 label 映射为 ATD/ATA，无需切换语言重新查询。 |
| 相同路线、航班号和整票件数的跨日互补记录 | 无冲突时可按提单口径合并，保留原始 group、flightDate 和各时间的证据引用，在 issues 说明原始节点关系与合并依据，件数只计一次。合并不代表独立核验为同一架次。 |
| 真实拆批、不同航段或冲突 | 分别保留，不能通过合并掩盖不完整或冲突。 |
| 多批到达覆盖整票 | 保留各独立批次的实际到达、件数和来源；不同到达时间不视为冲突。后端去重累计件数，选择末批实际到达作为整票 ATA。 |
| 首末有公路接驳 | 保留接驳路线，使用真正首末空运段的实际时间；公路时间不替代 ATD/ATA，空运到达不自动证明后续地面运输完成。 |
| 首发、末到及全票完成已有证据，中间时间缺失 | 可返回 complete；中间缺失或不影响首末判断的冲突保留在 issues。 |
| 本票实际时间原文明确，但航班格式、航段或件数尚无法确认 | 保留时间和引用，使用 time_context_unverified 指明 segmentId、field；涉及首发/末到时返回 partial。 |
| 原文没有该实际时间，或明确属于其他提单/航段 | 对应字段留空并说明具体原因，其他时间继续返回。 |
| 已取得完整记录 | 核对证据后输出，避免无目的地刷新、等待和重复验证。 |

## 与当前校验器的兼容

JSON 结构保持兼容：每个时间仍使用一个 `evidenceId` 和一段连续原文 `quote`。[校验器](../src/evidence.ts)与[上下文解析](../src/time-context.ts)同步支持共享页面信息，服务负责重新计算状态与首末汇总。

- 引用出自本次航司页面，排除交互控件中的输入值，保留框架、提单边界，防止借用另一票的数据。
- 共享上下文的路线、航班与整票件数可用于确认归属；解析失败或上下文不足时保留通过本票原文与实际标签校验的时间，记录待核实说明。明确矛盾仍拒绝；格式不兼容不等同于矛盾。
- 到达件数可从事件原文、明确表格列或已核实的唯一上下文读取；汇总只累计互不重复的末程到达批次。部分到达或待核实时间不能证明全票完成；件数/交付校验不清空实际时间，交付、理货和提货时间不能替代 ATA。
- 首末各批实际时间有效、可排序、归属明确并有全票完成证据时，可返回 complete；不要求分批时间相同，中间时间缺失不阻止 complete。首末拆批记录尚有未知时间、日期/时区无法排序或归属歧义时保持 partial。
- 首发最早值、末到最晚值、重复运输事件识别和件数合计由后端代码完成；模型负责提供逐条真实记录及证据，不自行生成 summary 字段。

## 验收

- `npm run check` 验证类型、现有自动化测试、Schema 生成和构建兼容性。
- 回归用虚构夹具验证跨日互补记录、共享标题与短引用、多票/多航班/真实拆批隔离、首末完成但中间时间缺失，以及首末冲突或数量不足。
- 真实查询仍需对照官网核实时间和记录归属；离线回放不等于模型已正确执行新流程。真实原文、截图和凭证保留在受控运行目录，不提交仓库。

编写方式参考 [OpenAI Docs：Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering) 中的目标、指令和上下文组织建议。
